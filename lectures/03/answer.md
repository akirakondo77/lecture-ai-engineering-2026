# 第3回 解答

## 演習

- 第1回（素のLLM）とエージェントの回答の違い：
  - 素のLLMは基礎・応用・発展についての一般論で答えたためこの講座の実際の概念とは異なる回答を生成した。エージェントはあらかじめ用意してあった用語集を検索し、「基礎（講義内容の確認）」「実装（自分でコードを書く）」「発展（調査や試行）」の3段階で、どれか1つに取り組めば宿題は完了すると正しく答えた。
- `--trace` で見えたツール呼び出し（ツール名と引数）：
  - 「LoRAとQLoRAの違いは？」では `search_glossary({'query': 'LoRA'})` と `search_glossary({'query': 'QLoRA'})`。
  - 確認問題の依頼では `make_quiz({'lecture': 2})`。第2回の用語から1つ選び、問題と答えを返した。
- 1つの質問での LLM 呼び出し回数（`requests`）：
  - いずれも2回。
- 追加したツールと、docstring に書いた説明：
  - `make_quiz(lecture: int) -> str`。指定した回の用語から1つを選び、確認問題と答えを返す。「『第2回の確認問題を出して』のように、復習用の問題を求められたときに使う」と説明した。

## 宿題

- 取り組んだレベル：発展
- やったこと：
　- Pi のシステムプロンプトを組み立てるソースコードを読み、構成要素を確認した。
  - 自作エージェントの INSTRUCTIONS と、「何が書かれていて、何が書かれていないか」の観点で比較した。
- 結果：
  - Pi は役割・ツール一覧・ルール・ドキュメントの場所・プロジェクト文脈・スキル・作業ディレクトリが示されていた。ドメイン固有の知識や、回答の出し方の制限は書かれていない。
  - INSTRUCTIONS は、役割、ツールの使い分け、「用語集にない」と伝える規則、回答末尾に第N回を示す規則、宿題は答えでなくヒントで導く規則を持つ。一方で、ツール一覧、口調・言語、ツール失敗時の動作、範囲外の質問への対応は書かれていない。
- 気づき・疑問：
  - Pi は汎用の土台を書いて固有の振る舞いを後から足す設計であり、INSTRUCTIONは講座特化のルールだけを直接書く設計で、思想が逆。
  - INSTRUCTIONはかなり曖昧な点がある。用語集の確認と回の要約取得が両方当てはまる質問の優先順位、回の指定がない質問での扱い、「ヒント」と「答え」の線引き。
  - Pi の docs セクションのように、ルールの発動条件（「聞かれたときだけ」）を明記する書き方は曖昧さを減らすのに使えそう。
